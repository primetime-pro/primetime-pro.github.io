# Цель

Опубликовать PrimeTime Pro как независимую бесплатную PWA на `https://primetime-pro.github.io/`, не изменяя клиентский PrimeTime и данные backend.

# Сделано

- Подготовлен отдельный статический пакет кабинета из опубликованной версии v824.
- Главный вход перенесён в корень сайта; клиентские ссылки оставлены на действующем PrimeTime.
- Созданы независимые manifest, service worker cache `primetime-pro-v6` и Pages workflow.
- Мобильное меню «Разделы» стало закрываемой панелью: выбор раздела, фон, Escape, Back, повторное нажатие и нижняя навигация закрывают её с восстановлением прокрутки.
- Мобильное расписание уплотнено без потери функций; счётчики получили короткие подписи «сегодня», «завтра», «впереди».
- Заголовок «Расписание» вынесен в отдельную строку; прозрачная сводка выровнена с «Новой записью» и не перекрывается вкладками.
- Мобильные акценты и иерархия записей/ручных/автоматических перерывов используют текущую тему без фиксированного зелёного; ссылки на клиентскую запись ведут на `https://primetime-booking.github.io/`.
- Лента дат поддерживает инерционный жест, недельные стрелки и центрирование выбранной даты.
- Подсказка о выборе свободного времени показывается только новому пользователю до первого фактического нажатия; для кабинета с существующими записями она сразу и навсегда скрывается.

# Проверено

- Исходная v824 опубликована и визуально проверена на 390, 760 и 1440 px.
- Локальные контрактные и браузерные проверки v6 проходят; матрица расписания проверена в 40 темах на 360/390/760/1440 px, настольный эталон — на 1440 px.
- GitHub Actions проверки и публикация v6 успешно завершены для `48a130e0bf1faee19d8d102d8b2fe5d9a0794f36`.
- Live `https://primetime-pro.github.io/` отдаёт v6, собственный PWA-кэш, стили v6 и актуальную ссылку на `https://primetime-booking.github.io/`; обновление service worker активировано через штатное уведомление.
- Тот же пакет расписания опубликован и проверен в действующем авторизованном кабинете: реальное нажатие свободного времени открывает карточку записи, а закрытие без сохранения не создаёт запись.

# Зафиксированные решения

- Бесплатный GitHub Pages; без домена и платных функций.
- Старый Pro не удаляется.
- Старый клиентский PrimeTime не переносится и не переименовывается.

# Ограничения и блокеры

- Новый auth origin должен быть разрешён в Supabase до окончательного переключения.
